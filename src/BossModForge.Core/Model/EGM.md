# Model

## Overview
Namespace `BossModForge.Core.Model`. Holds the immutable `EncounterModel` record graph, the builder that assembles it from replay/inference outputs (`Recording`, `Pull`, `Participant`, `AbilityCatalog`, `IGameData`), the timeline attachment step, deterministic JSON (de)serialization with schema validation, user-override application, and C# identifier sanitising. `EncounterModelBuilder` produces the model, `EncounterTimelineBuilder` attaches a `TimelineModel`, `OverridesApplier` applies `Overrides` on top, and `EncounterModelJson` persists it. This directory depends on `BossModForge.Core.Emit` (`ComponentPlanner.Place`, `StatesPlanner.StepStride` used in `EncounterTimelineBuilder`), and `Emit` consumes these model types. No subdirectories.

- `Overrides(ImmutableSortedDictionary<string, JsonElement> Values)` with `Overrides.Empty`, `IsEmpty` (`[JsonIgnore]`), `With(string key, JsonElement value)`, `Without(string key)` — [EncounterModel.cs: Overrides].
- `EncounterModelBuilder.HelperOid` (`const uint 0x233C`) and `EncounterModelBuilder.Build(Recording, ImmutableArray<Pull>, ImmutableArray<Participant>, AbilityCatalog, IGameData, BuildOptions? = null, IReadOnlyList<Recording>? sources = null) : EncounterModel` — [EncounterModelBuilder.cs: EncounterModelBuilder.Build]. `internal static SourceInfo SourceFor(Recording)` — [EncounterModelBuilder.cs: SourceFor].
- `EncounterModelJson.Serialize(EncounterModel) : string`, `Deserialize(string) : EncounterModel`, `Validate(string) : ImmutableArray<string>` — [EncounterModelJson.cs: EncounterModelJson].
- `internal static EncounterTimelineBuilder.Attach(EncounterModel, Recording, ImmutableArray<Pull>, AbilityCatalog, ImmutableArray<ReviewItem>.Builder) : EncounterModel` and `internal static StepName(ConsensusStep, ImmutableSortedDictionary<uint,string>, ImmutableArray<AbilityModel>) : string` — [EncounterTimelineBuilder.cs: Attach, StepName].
- `CSharpIdentifier.Sanitise(string name, string fallbackPrefix) : string` and `CSharpIdentifier.Dedupe(IEnumerable<string>) : ImmutableArray<string>` — [Identifiers.cs: CSharpIdentifier].

  - Constants `ModuleNameKey = "/encounter/moduleName"`, `NamespaceKey = "/encounter/namespace"`, `ArenaKey = "/arena"`.
  - Key builders `AbilityKey(uint aid, string field)` → `/abilities/{aid}/{field}`; `ParticipantKey(uint oid, string field)` → `/participants/{oid}/{field}`.

- Subdirectories: None.

## Invariants
- `EncounterModelBuilder.Build` substitutes empty collections for default `ImmutableArray` inputs (`pulls`, `participants`, and each `AbilityCatalog` member) and a new `BuildOptions()` when `options` is null [EncounterModelBuilder.cs: Build].
- `Build` emits `SchemaVersion: 1`, starts with `Review: []` and `Overrides.Empty`, and finally replaces `Review` with items re-numbered `"R1"`, `"R2"`, … in insertion order [EncounterModelBuilder.cs: Build].
- Primary OID is the most frequent `Pull.PrimaryOid`; ties broken by the smallest OID; `0` when there are no pulls; a Medium review item is added when more than one distinct primary OID is observed [EncounterModelBuilder.cs: PickPrimaryOid].
- Boss name falls back: participant `Name` → `IGameData.BNpcName(NameId)` → `"Boss"`. Module name = `CSharpIdentifier.Sanitise(options.ModuleName ?? bossName, "Encounter")`; namespace defaults to `"BossMod.Forge." + moduleName` [EncounterModelBuilder.cs: Build].
- `ParticipantModel`s exclude participants whose role is `Player` or `Pet` [EncounterModelBuilder.cs: Build].
- OID enum: sorted by OID; role `Boss` → `"Boss"`, `Helper` → `"Helper"`, others sanitised from name with fallback `"Actor"`; if any `Helper` role exists and no entry has `HelperOid`, an entry `(0x233C, "Helper")` is added; names deduped by suffixing integers [EncounterModelBuilder.cs: BuildOidEnum].
- AID enum / `AbilityModel`s include only `ActionType.Spell` abilities; non-spell abilities produce a Low review item (subject `ability.Name`, question "Non-spell action … omitted from AID enum") and are skipped. Names fall back to `"Ability{id}"`; entries sorted by action id [EncounterModelBuilder.cs: BuildAbilities].
- Ability confidence is the minimum score of the ability's, shape-fit's and classifier's confidence; `OmenUnknown` evidence is added for `TelegraphedAOE` with `Sheet is null` [EncounterModelBuilder.cs: BuildAbilities].
- `Build` also adds Medium review items: subject `arena`, "Arena appears to change at …" when the arena fit carries `ArenaChange` evidence [EncounterModelBuilder.cs: Build]; subject `shape`, "{name}: shape uncertain (kind, score)" when a shape fit has `ConfidenceBand.Low` [EncounterModelBuilder.cs: BuildAbilities].
- Classes `SharedTankbuster`, `Attract`, `Towers`, `Chasing`, `Instant`, `Interrupt` always add a Medium review item "has no emitted standard component" [EncounterModelBuilder.cs: BuildAbilities].
- Status/tether/icon enums are ordered by id; tether names `Tether{id}`, icon names `Icon{id}`, status names sanitised from name with fallback `Status{id}` [EncounterModelBuilder.cs: BuildStatuses, BuildTethers, BuildIcons].
- `EncounterTimelineBuilder.Attach`: loops in non-last phases are unrolled (`Repeats` × body + `TrailingPartial` steps) and a `LoopIgnored` evidence entry is added; only the last phase's loop becomes `TimelineModel.Loop` with `StartStep` offset by prior step count [EncounterTimelineBuilder.cs: Attach, UnrollIgnoredLoop].
- A phase is capped at 255 steps; further steps are dropped with a High review item "phase too long, truncated" [EncounterTimelineBuilder.cs: Attach].
- Phase `Kind` is `"HpThreshold"` when an HP threshold exists for the phase index, else `"Death"`; phase names are `"Phase{p}"` [EncounterTimelineBuilder.cs: Attach].
- When zero steps result, `phases` is cleared and a Low review item is added; timeline confidence is the last processed phase's `aligned.Confidence`, and `Confidence.Of(0)` only when no phase was processed [EncounterTimelineBuilder.cs: Attach].
- Each phase with an HP threshold adds a Medium `timeline` review item "HP N% phase split inferred from casting stop" [EncounterTimelineBuilder.cs: Attach].
- Step id format: `0x{(phaseIndex << 24) + StatesPlanner.StepStride * unfoldedIndex:X8}`; `Aid` is null for `StepKind.Targetable` steps; numeric AIDs inside `ReviewReason` are rewritten to AID enum names, longest decimal key first [EncounterTimelineBuilder.cs: ToStep].
- `ComponentPlanner.Place` is invoked after the timeline is attached; steps with a non-empty `Review` add a Medium `timeline` review item `"step {Id}: {Review}"` [EncounterTimelineBuilder.cs: Attach].
- `EncounterModelJson.Serialize`: camelCase, null properties omitted, indented, enums as strings (integers rejected), all object keys sorted ordinally, `schemaVersion` moved first, output ends with a single `\n` and uses `\n` newlines, `DateTime` written in round-trip `"O"` format [EncounterModelJson.cs: Serialize, CreateOptions, SortKeys, MoveSchemaVersionFirst, DateTimeOConverter].
- `uint→string` maps (`EnumNames`) serialize with keys ordered ordinally as decimal strings; `Overrides.Values` keys ordered ordinally [EncounterModelJson.cs: UIntStringDictionaryConverter, JsonElementDictionaryConverter].
- `Overrides.With` clones the `JsonElement`; keys always use `StringComparer.Ordinal` [EncounterModel.cs: Overrides.With, Overrides.Ordinal].
- `CSharpIdentifier.Sanitise`: splits on non-alphanumerics, upper-cases each part's first char, uses `fallbackPrefix` when empty, prefixes `_` if starting with a digit, prefixes `@` if the result is in the keyword set (case-sensitive) [Identifiers.cs: Sanitise]. `Dedupe` appends `1`, `2`, … to repeated names, preserving order [Identifiers.cs: Dedupe].
- `OverridesApplier.Apply` returns the same instance when `Overrides.IsEmpty` or when nothing changed; processes keys in ordinal order; invalid or unknown keys never throw for `JsonException`, `NotSupportedException`, `ArgumentException`, `InvalidOperationException`, `FormatException` — they add a review item with subject `"override"` (High "Malformed override value for {key}", or Low "Unknown override key {key}") [OverridesApplier.cs: Apply, Malformed, Unknown].
- Existing review items with subject `"override"` are discarded on each Apply, as are items whose subject matches the `Name` or `EnumName` of an ability overridden with `ignore: true`; new override review items are sorted by `Question` (ordinal) then `Severity`, appended after the kept items, and the whole list is re-numbered `R1…` [OverridesApplier.cs: Apply, NumberReviews, CompareOverrideReviews].
- Override key grammar: `/abilities/{uint}/{shape|class|enumName|ignore}` and `/participants/{uint}/{field}` (exactly one extra segment); an unknown aid/oid yields a High review item [OverridesApplier.cs: TryParseAbilityKey, TryParseParticipantKey, Apply].
- An `/abilities/{aid}/…` override applies to every `AbilityModel` with that `ActionId` [OverridesApplier.cs: AbilityIndexes, Apply].
- A `null` value for `shape` is accepted: it clears `Shape` and `ShapeFit` and sets the override confidence [OverridesApplier.cs: Apply, OverrideShape].
- An `enumName` override also updates `Enums.Aid` (ability) or `Enums.Oid` (participant) and the participant's `EnumName` [OverridesApplier.cs: Apply].
- Override effects: `enumName` collisions with another AID/OID yield a High review item and no rename; renaming the primary OID away from `"Boss"` is refused with a High review item; `ignore: true` sets `Class = Unclassified`, `Shape = null`, `ShapeFit = null`; `ignore: false` is a no-op; shape/class/arena overrides set `Confidence` to `Confidence.Of(1.0, reason)` and arena `Evidence` to a single `Override`/`user` entry [OverridesApplier.cs: Apply, OverrideShape, OverrideClass, OverrideIgnore, ApplyArenaOverride, KeepOrOverride].
- `ModuleName` override is sanitised via `CSharpIdentifier.Sanitise(raw, "Encounter")`; `Namespace` override is trimmed and must be non-empty [OverridesApplier.cs: Apply].

## Side Effects
- `EncounterModelBuilder.SourceFor` / `FileSha256` read the source recording file from disk (`File.Exists`, `File.OpenRead`, SHA-256) at `recording.Meta.Path`; returns `""` hash if the path is empty or missing [EncounterModelBuilder.cs: SourceFor, FileSha256].
- `EncounterModelBuilder.Build` calls `BoundsFitter.Fit`, `ShapeInference.Infer/Classify`, `MechanicClassifier.Classify`, and `IGameData` lookups (`BNpcName`, `ContentForTerritory`, `PlaceName`), and mutates the passed-in `ImmutableArray<ReviewItem>.Builder` during timeline attachment [EncounterModelBuilder.cs: Build; EncounterTimelineBuilder.cs: Attach].
- `EncounterModelJson.Validate` lazily loads the embedded resource `BossModForge.Core.em.v1.schema.json` once (static `Lazy<JsonSchema>`) and throws `InvalidOperationException` if the resource is missing, or `JsonException` (from `JsonDocument.Parse`) on malformed input; `Deserialize` throws `JsonException` on null result; `Serialize` throws `InvalidOperationException` if the root is not a JSON object [EncounterModelJson.cs: LoadSchema, Deserialize, Serialize].
- `CSharpIdentifier.Keywords` and `OverridesApplier` JSON options/evidence are static readonly state; no other static mutable state [Identifiers.cs: Keywords; OverridesApplier.cs: JsonOptions].
- `OverridesApplier.ToElement(...)` serializes via `JsonSerializer`. Other model files perform no network or other file I/O: None.
