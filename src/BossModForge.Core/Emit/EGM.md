# Emit

## Overview
Namespace `BossModForge.Core.Emit`. Turns an `EncounterModel` into a C# boss-module source file plus a `ForgeMd` review document. Output is parameterised by a flavor profile (`vbm` / `bmr`) whose JSON template set (`FlavorProfile.Templates`) supplies all code shapes. Pipeline: `ComponentPlanner` picks component classes and places their activate/deactivate points on the timeline; `StatesPlanner` converts the timeline into a `StatesPlan`; `StatesClassRenderer` renders the states class; `ShapeCSharp` renders shapes; `ModuleEmitter.Emit` assembles the file and calls `ForgeMdWriter`. This directory depends on `BossModForge.Core.Model` (and `Inference`); `Model/EncounterTimelineBuilder` in turn calls `ComponentPlanner.Place` and `StatesPlanner.StepStride`. No subdirectories.

## Invariants
- `FlavorProfile.Load`: JSON read case-insensitively with comments skipped; flavor is `Bmr` only when the `flavor` string equals `"bmr"` (case-insensitive), otherwise `Vbm`; `RootNamespace` defaults to `"BossMod"`; other string fields default to `""`; the JSON field `helperOid` is stored in `HelperComment`; templates sorted ordinally [Flavor.cs: Load].
- All template lookups require the key to exist, otherwise `InvalidOperationException("Flavor template '<key>' is missing.")` [ShapeCSharp.cs: T; StatesClassRenderer.cs: T; VbmProfile.cs: Template]. `ModuleEmitter.BuildComponents` indexes `Templates["componentClass"]` directly (a missing key throws `KeyNotFoundException`) [ModuleEmitter.cs: BuildComponents].
- `ShapeCSharp.Render` supports `Circle`, `Donut`, `Cone`, `Rect` (uses `shapeRectBack` when `LengthBack > 0`), `Cross`; any other kind throws `NotSupportedException` [ShapeCSharp.cs: Render].
- `ShapeCSharp.Num` rounds to one decimal (away from zero); values within 0.05 of an integer print as an int, otherwise `"0.0"` format with suffix `f`; culture invariant [ShapeCSharp.cs: Num].
- `VbmProfile.ArenaBounds`: `"Square"`, `"Rect"`, `"Custom"` select dedicated templates, any other kind uses `boundsCircle` [VbmProfile.cs: ArenaBounds]. `ComponentCtor` throws `NotSupportedException` for kinds other than `SimpleAOEs`, `SimpleAOEGroups`, `LocationTargetedAOEs`, `RaidwideCast`, `SingleTargetCast`, `SpreadFromCastTargets`, `StackWithCastTargets`, `KnockbackFromCastTarget`, `CastGaze`; required `args` keys are indexed directly [VbmProfile.cs: ComponentCtor].
- `VbmProfile.EnumDeclaration` writes values in hex (`0x…`) only when `enumName == "OID"`, decimal otherwise; uses `\n` newlines [VbmProfile.cs: EnumDeclaration]. `ModuleDeclaration` splits `center` on `,` with defaults `"0"` [VbmProfile.cs: ModuleDeclaration].
- `ComponentPlanner.Plan` unit order: sorted by first action id, class names deduped via `CSharpIdentifier.Dedupe`. Kinds: `Raidwide`→`RaidwideCast`; `TelegraphedAOE`/`HiddenAOE` with non-null `Shape` grouped by equal `Shape` → `LocationTargetedAOEs` (single ability, Circle with `ShapeOrigin.CastLocation`), `SimpleAOEs` (single otherwise), or `SimpleAOEGroups` (class name joined with `And` when ≤3 members, else `{first}AndOthers`); `Tankbuster`→`SingleTargetCast`; `Spread`→`SpreadFromCastTargets`; `Stack`→`StackWithCastTargets`; `Knockback`→`KnockbackFromCastTarget`; `Gaze`→`CastGaze` [ComponentPlanner.cs: Plan].
- `ComponentPlanner.Place`: returns `em` unchanged when `Timeline is null`. A unit is placed at phase level (added to `PhaseModel.Activate`) when it is never anchored (all phases), is used within the loop range, or appears in ≥2 phases; otherwise the first hit step gets `Activate` and the last hit step gets `Deactivate`. Activate/deactivate lists are de-duplicated and ordinally sorted [ComponentPlanner.cs: Place, WithActivate, WithDeactivate].
- `StatesPlanner.Plan`: returns a plan with empty `Phases` and `TrivialActivate` = all component class names when `Timeline` is null or has no steps. Only the last phase can carry a `LoopPlan`, and only when `Loop.StartStep` lies within that phase; step offsets are `index * StepStride`, loop stride is `StepStride * Loop.Length`, tail offset is `FirstCallOffset + stride * Repeats`. Unknown AIDs resolve to `"Ability{id}"`. Step review comment format: `TODO(forge:{id}, {sev}): {Review}` with `R?`/`Medium` when no matching timeline review item [StatesPlanner.cs: Plan, ToStep].
- `StatesClassRenderer.Render`: output is `class {ModuleName}States : StateMachineBuilder`; empty phases render the `trivialPhase` template with `activateOnEnter` links; phase kind `"HpThreshold"` uses `simplePhase` + `phaseHpUpdate`, other kinds `deathPhase`; step kinds `CastMulti`, `Timeout`, `Targetable` have dedicated templates, others use `stateCast` (AID `"Unknown"` when `AidMember` null); a `stateTail` with `id + 0xFF0000` is emitted for the last phase or any phase with a loop; trailing newlines are trimmed [StatesClassRenderer.cs: Render, RenderPhaseMethod, RenderStep].
- `ModuleEmitter.Emit` always adds review item `E1` (Medium, "Set Expansion/Category"); adds High `flavor` item when `!profile.Profile.Verified`; adds High `arena` item when `em.Arena.Kind == "Custom"`; emitted file is `{ModuleName}.cs`, `\r\n` normalised to `\n`; namespace is `options.Namespace ?? em.Encounter.Namespace`; `SID`/`IconID`/`TetherID` enums emitted only when non-empty; `OID` and `AID` always emitted; group type is `"CFC"` with `CfcId` and `BossNameId` [ModuleEmitter.cs: Emit].
- `ModuleEmitter.Emit` always writes the literal line `// TODO(forge:E1) Set Expansion/Category` before the ModuleInfo attribute. `ModuleInfoArgs.Contributors` and `PrimaryActorOid` are passed but unused: `VbmProfile.ModuleInfoAttribute` substitutes only `{maturity}`, `{groupType}`, `{groupId}`, `{nameId}` [ModuleEmitter.cs: Emit; VbmProfile.cs: ModuleInfoAttribute].
- The `center` string is `"{CenterX:F0}, {CenterZ:F0}"` (invariant culture), so centre coordinates are rounded to whole numbers [ModuleEmitter.cs: Emit].
- `StatesClassRenderer` renders `CastMulti` AIDs as `"AID." + member` and bypasses `IdCast`, so Bmr output has no `(uint)` cast there [StatesClassRenderer.cs: RenderStep].
- Component args: `radius` for Spread/Stack and `distance` for Knockback come from `MechanicClassifier.ParamsKind` evidence `key=value` tokens, falling back to Circle shape radius (radius only) then `"6"` / `"10"`; classes `SharedTankbuster`, `Attract`, `Towers`, `Chasing`, `Instant`, `Interrupt` emit a `// TODO(forge) …` comment line instead of a component [ModuleEmitter.cs: BuildComponents, MechanicParam]. When an aid is shared by multiple OIDs the first `AbilityModel` wins [ModuleEmitter.cs: BuildComponents].
- `ModuleEmitter.OidMembers`: `Boss` ordered first, `Helper` (or `HelperOid`) moved to index 1 (when the helper is already at index 0 and index 1 is `Boss`, the two are swapped); comment format `R{radius:F3}, x{count}` (+ `, Helper type` for Helper); default radius 0.5 when participant missing [ModuleEmitter.cs: OidMembers].
- `ForgeMdWriter.Write` output sections in order: header, `## Sources`, `## Arena`, `## Shapes`, `## Timeline`, `## Review`, `## Participants`; ends with `\n`, `\r\n` normalised to `\n`; merged-recording warning added when `Sources.Length > 1`; `## Shapes`, `## Review` and `## Timeline` (when `Timeline` is null) print `(none)` when empty, but `## Sources` and `## Participants` print nothing when empty [ForgeMdWriter.cs: Write, WriteTimeline]. `WriteTimeline` hardcodes `Loop: Rotation0`, whereas `StatesPlanner` names the emitted loop method `"Rotation" + p` with `p` = last phase index, so for multi-phase timelines the review doc and the emitted code disagree [ForgeMdWriter.cs:203, StatesPlanner.cs:39].
- `ProfileFor` loads `bmr.json` for `Flavor.Bmr`, otherwise `vbm.json`, from the given directory [ModuleEmitter.cs: ProfileFor]. `ResolveFlavorsDirectory` returns `specified` if it exists; else searches parents of `AppContext.BaseDirectory` then `Directory.GetCurrentDirectory()` for a `flavors/` directory containing `vbm.json`; else returns `{BaseDirectory}/flavors` [ModuleEmitter.cs: ResolveFlavorsDirectory].

## Side Effects
- `FlavorProfile.Load` reads a file (`File.ReadAllText`) and throws `JsonException` if it deserializes to null [Flavor.cs: Load].
- `ModuleEmitter.ResolveFlavorsDirectory` reads the filesystem (`Directory.Exists`, `File.Exists`, `Directory.GetCurrentDirectory`, `AppContext.BaseDirectory`) [ModuleEmitter.cs: ResolveFlavorsDirectory]; `ProfileFor` reads the flavor JSON via `FlavorProfile.Load` [ModuleEmitter.cs: ProfileFor].
- `ModuleEmitter.Emit` itself does not write files; it returns content in `EmitResult` (pure string generation) [ModuleEmitter.cs: Emit].
- `ComponentPlanner.Place` returns a new `EncounterModel` (immutable `with` copies; no mutation of input) [ComponentPlanner.cs: Place].
- Static state: `FlavorProfile.FlavorJsonOptions` readonly only. No network access, locks, or other mutable static state: None.
